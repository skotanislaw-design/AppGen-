# Nomos Audit — Έλεγχος Νομικής Πληρότητας Δικογράφων

AI agent του γραφείου **Skotanis & Associates** που δέχεται έτοιμο δικόγραφο —
ποινικό, αστικό, διοικητικό ή εξώδικο — και εκτελεί **αυστηρό έλεγχο νομικής
πληρότητας**, τυπικό και ουσιαστικό, με τελικό αποτέλεσμα **επί τοις 100** και
ιεραρχημένες **βελτιωτικές προτάσεις**.

## Πώς λειτουργεί ο agent

Το pipeline έχει πέντε στάδια:

1. **Ταξινόμηση (διαλογή)** — Ένας ουδέτερος «δικονομολόγος διαλογής»
   (Claude Opus 4.8) αναγνωρίζει το είδος του εγγράφου (π.χ. αγωγή, μηνυτήρια
   αναφορά, αίτηση ακυρώσεως, εξώδικο), τον κλάδο δικαίου, τον σκοπό και το
   δικονομικό πλαίσιο. Ο χρήστης μπορεί εναλλακτικά να ορίσει ρητά το είδος.
2. **Ανάθεση σε ειδικό του κλάδου** — Ο κατ' ουσίαν έλεγχος **δεν** γίνεται
   από γενικό ελεγκτή. Το δικόγραφο δρομολογείται σε εξειδικευμένο ελεγκτή με
   δικό του γνωστικό προφίλ και δόγμα ελέγχου (`backend/app/pipeline/experts.py`):

   | Κλάδος | Ελεγκτής | Εστίαση |
   |---|---|---|
   | Ποινικά | **Ποινικολόγος** | Υπόσταση εγκλήματος, παραγραφή/προθεσμία έγκλησης, ακυρότητες ΚΠΔ, in dubio pro reo, αυτοτελείς ισχυρισμοί |
   | Αστικά | **Αστικολόγος–Δικονομολόγος** | Ορισμένο/αοριστία (216 ΚΠολΔ), νομιμοποίηση, δικονομικά απαράδεκτα, ενστάσεις με θεμελίωση |
   | Διοικητικά | **Διοικητικολόγος** | Παραδεκτό (εκτελεστότητα, προθεσμίες, έννομο συμφέρον), φύση λόγων ακυρωτικής/ουσίας, αιτιολογία, αναλογικότητα |
   | Εξώδικα | **Ειδικός Εξωδικαστικής Πρακτικής** | Έννομα αποτελέσματα δήλωσης, δυνητικές ομολογίες, ποινικοί κίνδυνοι διατυπώσεων |
   | Λοιπά | **Γενικός Νομικός Ελεγκτής** | Καθολικά κριτήρια + σύσταση ελέγχου από ειδικό |

   Αν το έγγραφο εμπλέκει παρεμπιπτόντως ζητήματα άλλου κλάδου, ο ειδικός τα
   καταγράφει ρητά με σύσταση διασταύρωσης από τον οικείο ειδικό.
3. **Έλεγχος πληρότητας** — Το έγγραφο αξιολογείται κριτήριο προς κριτήριο
   έναντι τυποποιημένου checklist: 12 καθολικά κριτήρια (διάδικοι, αίτημα,
   ιστορική βάση, υπαγωγή, τεκμηρίωση, δικανικός λόγος κ.λπ.) **συν** τα ειδικά
   κριτήρια του είδους με τις οικείες διατάξεις (π.χ. ἄρθρ. 118/216 ΚΠολΔ για
   αγωγή, ἄρθρ. 46-48 ΠΔ 18/1989 για αίτηση ακυρώσεως, ἄρθρ. 114 ΠΚ & 42 ΚΠΔ
   για έγκληση, fumus boni iuris / periculum in mora για αναστολές). Κάθε κρίση
   συνοδεύεται από τεκμηρίωση με αυτούσιο απόσπασμα του εγγράφου. Το μοντέλο
   καταγράφει επιπλέον ευρήματα εκτός checklist και βελτιωτικές προτάσεις.
4. **Πρότυπο Γραφείου** — Ο «Επιμελητής Δικανικού Λόγου» κρίνει αν το
   δικόγραφο μπορεί να φέρει το λογότυπο της εταιρείας. Το πρότυπο είναι
   διπλό: (α) **υποδειγματικό επίπεδο** γραφής — πλήρεις νομολογιακές
   παραπομπές, θεωρία κατ' όνομα, φυσικός δικανικός ρυθμός, ενότητες που
   κλείνουν με ισχυρισμό· (β) **μηδενική ανοχή σε ίχνη AI** — ανιχνεύονται
   δομικές ενδείξεις (λίστες/συμμετρία στο σώμα), τυποποιημένη AI
   φρασεολογία («Συνοψίζοντας», «Αξίζει να επισημανθεί»), μηχανικός ρυθμός,
   γραφειοκρατικό αντί δικανικό ύφος και ρηχή τεκμηρίωση. Κάθε εύρημα
   συνοδεύεται από το επίμαχο απόσπασμα και προτεινόμενη αναδιατύπωση σε
   φυσικό δικανικό λόγο. Ετυμηγορία: `human_register` / `borderline` /
   `ai_marked`.
5. **Βαθμολόγηση** — Η βαθμολογία υπολογίζεται **ντετερμινιστικά στον κώδικα**
   (όχι από το μοντέλο): σταθμισμένος μέσος ανά κατηγορία (Τυπική πληρότητα
   25%, Ουσιαστική πληρότητα 35%, Νομική τεκμηρίωση 25%, Δομή & νομικός λόγος
   15%). Η πλήρης απουσία **κρίσιμου** στοιχείου (π.χ. αίτημα, προθεσμία,
   έννομο συμφέρον) θέτει οροφή 45% — η ατελής κάλυψή του, οροφή 70%.
   Επιπλέον, η πύλη του Προτύπου Γραφείου δεν επιτρέπει σε έγγραφο με σαφή
   ίχνη AI (`ai_marked`) να βαθμολογηθεί πάνω από 55%, ούτε σε οριακό
   (`borderline`) να χαρακτηριστεί «Άρτιο» (οροφή 85%).

Η δομημένη έξοδος του μοντέλου επιβάλλεται με structured outputs
(`output_config.format` + JSON Schema), οπότε η απόκριση είναι εγγυημένα
έγκυρη και μηχανικά επεξεργάσιμη.

## Βιβλιοθήκη Υποδειγμάτων

Η εφαρμογή περιλαμβάνει **βιβλιοθήκη υποδειγματικών σχεδίων δικογράφων**
(`backend/app/exemplars/`) προς χρήση από τους συνεργάτες του γραφείου ως
μέτρο του άρτιου — για τη σωστή νομική, ουσιαστική και δομική «οικονομία»
κάθε είδους:

| Κλάδος | Υπόδειγμα |
|---|---|
| Ποινικά | Έγκληση για υπεξαίρεση (375 ΠΚ) · Απολογητικό υπόμνημα επί απάτης (386 ΠΚ) |
| Αστικά | Αγωγή αμοιβής έργου (681/694 ΑΚ) · Αίτηση συντηρητικής κατάσχεσης (682 επ. ΚΠολΔ) |
| Διοικητικά | Προσφυγή κατά καταλογισμού ΦΠΑ · Αίτηση ακυρώσεως · Αίτηση αναστολής |
| Εξώδικα | Εξώδικη πρόσκληση καταβολής μισθωμάτων |

Κάθε υπόδειγμα συνοδεύεται από **σημειώσεις συντάξεως** (γιατί κάθε τμήμα
βρίσκεται εκεί που βρίσκεται και σε αυτή την αναλογία, ποιες παγίδες
προλαμβάνει) και **κρίσιμες διατάξεις**. Τα σημεία εξατομίκευσης φέρουν
[ΣΥΜΠΛΗΡΩΣΤΕ]· η νομολογία σημειώνεται πάντοτε ως θέση προς επαλήθευση —
ποτέ με ανεπαλήθευτο αριθμό αποφάσεως.

Τα υποδείγματα τροφοδοτούν και το στάδιο 2 του ελέγχου: ο ειδικός του
κλάδου λαμβάνει το υπόδειγμα του είδους ως **πρότυπο αναφοράς** και συγκρίνει
το ελεγχόμενο δικόγραφο με αυτό ως προς τη δομική πληρότητα και τη
θεμελίωση (χωρίς να απαιτεί λεκτική ταύτιση). Στο UI είναι προσβάσιμα από
την καρτέλα «Βιβλιοθήκη Υποδειγμάτων», με προβολή του σχεδίου σε μορφή
εγγράφου και αντιγραφή με ένα κλικ.

## Υποστηριζόμενα είδη δικογράφων

| Κλάδος | Είδη |
|---|---|
| Ποινικά | Μηνυτήρια αναφορά/έγκληση, απολογητικό υπόμνημα, έφεση |
| Αστικά | Αγωγή, προτάσεις, ασφαλιστικά μέτρα, ανακοπή (632/933 ΚΠολΔ), έφεση |
| Διοικητικά | Προσφυγή ΚΔιοικΔ, αίτηση ακυρώσεως (ΣτΕ/ΔΕφ), αίτηση αναστολής, ενδικοφανής προσφυγή |
| Εξώδικα | Εξώδικη δήλωση / πρόσκληση / διαμαρτυρία |
| Λοιπά | Generic fallback με τα καθολικά κριτήρια |

## Τεχνολογίες

- **Backend**: FastAPI (Python 3.12) · Anthropic SDK (`claude-opus-4-8`,
  adaptive thinking, structured outputs, prompt caching) · pypdf / python-docx
  για εξαγωγή κειμένου · SSE για ζωντανή πρόοδο σταδίων.
- **Frontend**: React 18 + Vite + TypeScript + Tailwind CSS, με το design
  system της εταιρείας (navy/gold, glass-morphism, Cormorant Garamond +
  Montserrat).

## Εκτέλεση

### Με Docker (προτεινόμενο)

```bash
cp .env.example .env   # συμπληρώστε ANTHROPIC_API_KEY
docker compose up --build
# Εφαρμογή: http://localhost:8080
```

### Τοπικά (development)

```bash
# Backend
cd backend
pip install -r requirements-dev.txt
export ANTHROPIC_API_KEY=sk-ant-...
uvicorn app.main:app --reload          # http://localhost:8000

# Frontend (δεύτερο terminal)
cd frontend
npm install
npm run dev                            # http://localhost:5173
```

### Tests

```bash
cd backend && python -m pytest
```

## API

| Endpoint | Περιγραφή |
|---|---|
| `GET /api/health` | Έλεγχος λειτουργίας |
| `GET /api/document-types` | Μητρώο υποστηριζόμενων ειδών |
| `GET /api/exemplars` | Κατάλογος υποδειγματικών σχεδίων |
| `GET /api/exemplars/{doc_type}` | Πλήρες υπόδειγμα με σημειώσεις συντάξεως |
| `POST /api/extract` | Εξαγωγή κειμένου από PDF/DOCX/TXT (multipart) |
| `POST /api/analyze` | Πλήρης ανάλυση — επιστρέφει `AuditReport` (JSON) |
| `POST /api/analyze/stream` | Ίδια ανάλυση με SSE γεγονότα προόδου |

Σώμα αιτήματος ανάλυσης:

```json
{
  "text": "…πλήρες κείμενο δικογράφου…",
  "context": "προαιρετικό πλαίσιο/σκοπός",
  "doc_type_hint": "agogi"
}
```

Αν οριστεί `NOMOS_AUDIT_API_KEY` στο περιβάλλον, όλα τα endpoints ανάλυσης
απαιτούν header `Authorization: Bearer <key>`.

## Ρυθμίσεις (env)

| Μεταβλητή | Προεπιλογή | Περιγραφή |
|---|---|---|
| `ANTHROPIC_API_KEY` | — | Κλειδί Claude API (υποχρεωτικό) |

## Επέκταση

- **Νέο είδος δικογράφου**: προσθέστε `DocumentTypeSpec` με κριτήρια στο
  `backend/app/pipeline/checklists.py` — ο classifier, ο auditor και το UI το
  παραλαμβάνουν αυτόματα.
- **Νέος ειδικός ελεγκτής** (π.χ. εργατολόγος, φορολογικός): προσθέστε
  `ExpertProfile` στο `backend/app/pipeline/experts.py` και αντιστοιχίστε τον
  κλάδο στα είδη του μητρώου — η δρομολόγηση γίνεται αυτόματα βάσει κλάδου.
- **Νέο υπόδειγμα**: προσθέστε το σχέδιο ως `.md` στο
  `backend/app/exemplars/` και καταχωρίστε `Exemplar` στο registry — το API,
  το UI και το πρότυπο αναφοράς του ελέγχου το παραλαμβάνουν αυτόματα.
- **Ενσωμάτωση στο Nomos One**: το API είναι stateless — αρκεί mount του
  router πίσω από το JWT/RBAC του LPMS και κλήση από το module Documents.
